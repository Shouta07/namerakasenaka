# システム監査報告書 — namerakasenaka / Accord（2026-07）

**対象**: 本リポジトリ全体（senacare CRM・提案ページ群・Accord デモ・設計ドキュメント）
**方法**: 実測主義 — git状態 / tsc / vitest 110件 / npm audit / 公開面・秘匿情報・コンプラの grep 検査
**時点の健全性**: 型チェック クリーン ／ テスト 110/110 パス ／ XSSパターン(dangerouslySetInnerHTML)なし ／
secrets は .env.example のみ追跡・.gitignore 適切 ／ service_role はサーバ側のみ ／ 禁止語フィルタは全AI・API経路に適用済み

> 総評: **アプリの中身は健全。リスクの重心は「運用構成」と「公開面」にある。**

---

## 🔴 高（すぐ対処すべき）

### R1. 作業ブランチ1本が「開発・本番・唯一のバックアップ」を兼ねている
**証拠**: リモートブランチは `claude/senacare-requirements-doc-OybPh` のみ（main 不在）。CI なし。ブランチ保護なし。
Vercel の営業デモはこのブランチに直結 = **push した瞬間、壊れた状態が商談環境に出る**。
**実証**: 本監査中、作業環境が11コミット過去へ巻き戻る事象が実際に発生（プッシュ済みだったため無損失で復旧）。
裏返せば **push 漏れ＝全損** の構成。
**対処**: main を作成しデフォルト化 → Vercel Production を main に接続 → 作業ブランチからは Preview のみ。
GitHub Actions で `tsc + vitest` を必須化。商談前は安定タグを切る。

### R2. 実在人物名が公開URLに掲載されている（許諾記録なし）
**証拠**: `真弓先生`（実在の医師・「監修」表記つき）・`田村さん`（実在のクライアント）が
公開ページ `/plans` `/story` `/lessons-preview` `/hub` に記名。
**リスク**: 本人の掲載許諾が記録されていない。特に**医師名＋「監修」表示**は、無許諾なら信頼毀損・法的リスクの両方。
商談が壊れる可能性すらある（本人がURLを見た場合）。
**対処**: 掲載許諾を書面で取る（最優先）／取れるまで「監修ドクター」「オーナー」等の仮名表記へ差し替え。

### R3. デモモード設計により全画面が認証なしで公開
**証拠**: `isDemoMode()`（Supabase env 未設定）で middleware が全ルートを素通し。
admin CRM・顧客詳細・売上画面まで誰でも閲覧可能。`/hub` は内部資料の存在
（契約書ドラフト・見積PPT・事業戦略docの名前）まで一覧公開している。
**リスク**: 競合・取引先が営業戦略/価格/資料体系を観察できる。B4A等の公開サイトが403で守られているのと対照的。
**対処**: `/hub` に簡易パスコード（または noindex + 推測不能URL化）。デモ公開範囲を「見せたい画面」に限定するか、
少なくとも robots で noindex。商談配布URLと公開URLを分ける。

### R4.（SaaS化ゲート）同意ゲート・削除カスケードが文書のみ
**証拠**: `recordLineSend` はクライアント処理（デモとして意図的）。403サーバ強制・患者削除カスケードは設計書記載のみ。
**対処**: 「課金開始（M2）の前提条件」として明文化済みの通り、実装完了を課金のブロッカーにする。現時点では追跡でよい。

## 🟡 中（計画的に対処）

### R5. ドキュメント⇄コードの乖離（真実の源が割れている）
**証拠**: cull(v2.2) 後も `saas-design.md` §2.4 に **ai-minutes / staff-kpi（レジストリから削除済み）** が残存。
§3.1 プラン表に「テーマパック¥100,000」「カスタム練習シナリオ3本」「顧客200名上限」等、
**レジストリに存在しない販売条件**が記載。`pain-coverage.md` も一部 cull 前提。
**リスク**: 商談で資料ごとに言うことが違う。実装と約束のズレ。
**対処**: saas-design §2.4/§3.1 を v2.2 に整合改訂し、「販売条件はレジストリが唯一の源、docsは参照」ルールを明記。

### R6. 依存パッケージ脆弱性 3件（high 1 / moderate 2）
**証拠**: `npm audit --omit=dev` → form-data 4.0.0-4.0.5 CRLFインジェクション(high)、postcss ほか(moderate)。
いずれも `npm audit fix` で修正可能（破壊的変更なし見込み）。
**対処**: `npm audit fix` 実行 + CI に audit を組み込み。

### R7. 架空データが「実績」に見える
**証拠**: 公開ページの「成約率61%」「38名中9名が再来店予約」等はデモ数値。Accord 側フッターに
「本画面はデモです」はあるが、`/story` `/plans` の事例的数字には架空明示が薄い。
**リスク**: 実績と誤認されたまま商談が進むと信頼毀損。医療系では誇大表示の指摘リスク。
**対処**: 数字を含む公開ページに「数値はデモ用の架空データ」注記を常設。実績が出たら実数に差し替え。

### R8. 共有端末（サロンiPad）× localStorage
**証拠**: デモの入力（フォローメモ・練習結果・トグル）は端末の localStorage に残存。
**リスク**: 店頭デモで**実顧客名を入力されると、その端末に残り続ける**。
**対処**: デモ画面に「実在のお客様の情報は入力しないでください」注記 + 「デモデータをリセット」ボタン。

### R9. リポジトリ可視性・資料の秘匿
**証拠**: repo 内に価格戦略・契約書ドラフト・競合分析。可視性(private確認)は本環境から検証不能。
**対処**: GitHub で private であることを確認。外部共有時は docs/ を除外する運用を明文化。
