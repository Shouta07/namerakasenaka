# 検査結果の取り込みと、同意にもとづく可視化

**方針**: 患者には極力入力させない。データは施術者が投入し、
**患者の同意を得たうえで**患者側に可視化する。

---

## 1. なぜこの形か

続かない仕組みを作らないため。記録を患者に任せると、最初の2週間で止まる。
一方で、検査結果は必ず店舗の手元に届く。**すでに手元にあるものを投入するだけ**なら、
現場の追加作業はドラッグ1回で済み、患者の負担はゼロになる。

同意を「フラグ」にしないのも同じ理由。
`consent: true` は、あとから「誰がいつ何に同意したのか」を説明できない。
説明できない同意は、事故が起きたときに同意ではなかったことになる。

## 2. 流れ

```
[施術者]  検査票をドラッグ&ドロップ / 貼り付け
              ↓  parseLabReport()      純関数・38テスト
[施術者]  読み取り結果を目で確認
              ↓  addStoredLabImport()  publishedAt = null（まだ見えない）
[施術者]  同意を確認して記録
              ↓  POST /api/labtest/publish   同意が無ければ 403
[患者]    /c/guide に可視化される
```

**3つの関門**があり、どれかが欠けたら患者には出ない。

1. 人が読み取り結果を確認している
2. 施術者が「表示する」を押している（`publishedAt`）
3. **いま**同意が有効である（過去に同意していただけでは足りない）

3 を毎回見るのが要点。同意を取り消した瞬間から、公開済みの検査も見えなくなる。

## 4. パーサの決めごと

**読めなかった行を捨てない。** 捨てると「入れたはずの値が無い」事故になる。
認識できた行と、できなかった行（理由・行番号つき）を両方返し、画面に出す。

対応している揺れ:

- 区切り: タブ / カンマ / 空白2つ以上
- 項目名: 全角英字（`ビタミンＤ`）、全角かっこ、大文字小文字、英語名、`AST(GOT)` の併記
  — NFKC 正規化で吸収する
- 数値: 桁区切りカンマ、`H` / `L` の判定記号、`<0.5` の境界値
- 単位: `μg/L` ↔ `ng/ml`（同値）、`nmol/L` → `ng/ml`（÷2.496）
  **値が変わる換算のときだけ**「換算しました」と出す。1:1 の呼び名違いで
  警告を出すと、本当に確認すべき項目が埋もれる
- ヘッダ行・区切り線は自動で読み飛ばす（読めなかった行に数えない）

辞書に無い項目は取り込まない。意味づけ（何を見ている数字か、肌との関わり）が
書けない項目を図にしても、患者には何も伝わらないため。

## 5. 同意の設計

目的ごとに分ける。まとめて取ると、あとで説明できない。

| scope | 何に対する同意か |
|---|---|
| `labtest_view` | 検査結果を、ご本人の画面に表示する |
| `line_share` | 経過を LINE で受け取る |
| `photo_view` | 施術前後の写真を、ご本人の画面に表示する |

記録に残すもの: **いつ・誰が確認したか・どう確認したか（口頭 / 署名 / LINE）**。
取り消しは記録を消さず `revokedAt` を立てる — 「取り消した」ことも履歴。

判定は「記録が無い」と「取り消された」を書き分ける。
取り消しは、もう一度お願いする前に理由を確認すべき状態なので、同じ扱いにしない。

## 6. 実測で確認したこと

本番ビルド上で、ブラウザを操作して確認した:

- 同意なしでは公開ボタンが押せない **かつ** UI を迂回して API を直接叩いても
  `403 consent_required` が返る（画面だけの制限になっていない）
- 同意を記録 → 公開 → 患者側 `/c/guide` に取り込んだ値が出る
- 同意を取り消す → 患者側から即座に消える
- 取り消し後に API を直接叩いても `403`（理由は「取り消されています」と書き分け）
- 1回目の検査しか無いときは「前回」の破線を出さず、その旨を書く

## 7. 残っていること

- **PDF の直接読み取り**。いまは「表を選択してコピーして貼り付け」と案内して逃がしている。
  黙って失敗させないことを優先した
- **本番の永続化**。`lab_imports` / `consents` テーブルと RLS。
  いまはデモの localStorage で、API 側の同意判定だけが本番と同じ関数を通る
- **LINE 送信の同意強制**。`canSendLine()` は用意済みで、B4 の配信実装と同時に挿す
