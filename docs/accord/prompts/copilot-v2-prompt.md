# Accord v2 改善プロンプト — クリニック経営コパイロットへの進化

> 使い方: このプロンプトを Claude Code に丸ごと投げる。1回で全部やらせず、
> 「やること」の 1→2→3… の順に区切って実行させてもよい。

## あなたの役割

あなたは Accord（クリニック・サロン向けSaaS）のプロダクト責任者兼リードエンジニアです。
既存の設計資産と実装を**壊さず・捨てず**、Accord を「初回カウンセリング支援ツール」から
**「クリニック経営コパイロット — 既存システムの上に乗るAIレイヤー」**へ進化させてください。

## 前提資料（必読・このリポジトリにある）

1. `docs/accord/saas-design.md` — 事業・技術設計 v1.0（MRR100万・プラン・ユニットエコノミクス）
2. `docs/accord/topping-architecture.md` — トッピング機構設計 v1.0（生地/チーズ/トッピング/パック/サービスの5階層）
3. `src/lib/toppings/` — **実装済み**のレジストリ・can()判定・プラン写像（テスト18本 green）
4. `src/app/accord/` — デモ4画面 + /pricing（動作中。営業資産なので壊さない）
5. `src/lib/retention/`・`src/lib/evidence/` — 純関数のリスク検知・効果集計エンジン（コパイロットの部品になる）

## 今回の戦略転換（なぜ変えるか）

これまでの Accord は「初回カウンセリングの成約」に特化していた。これは正しい入口だが、
自由診療・美容クリニックのペインを棚卸しすると、**院長が本当に困っているのは
「毎日の数字が見えない・次に何をすべきか分からない」という経営管理**であり、
AI時代に最も価値が高いのは個別機能（AI受付・AIカルテ）ではなく
**数字を見せて次の一手まで提案する「経営コパイロット」**である。

ポジショニングも更新する: 電子カルテ・予約システムと戦わない。
**既存システムの上に乗るAIレイヤー**として、それらのデータを吸い上げ、
「気づき → 打ち手の提案 → Accord内でワンタップ実行 → 効果測定」のループを回す。
これが差別化であり、導入ハードルを下げる。

## ペイン → 価値マップ（設計の背骨として文書に反映すること）

| # | ペイン領域 | 代表ペイン | Accord の価値 | 既存資産との対応 |
|---|---|---|---|---|
| 1 | 集客・経営 | CAC高騰 / リピート率低 / LTV伸びない / キャンセル多 | リピート率・LTV向上、自動フォロー、患者分析 | follow-loop / at-risk（既存）+ LTV分析（新規） |
| 2 | カウンセリング | 成約率が人で違う / ノウハウ属人化 / 新人教育が重い | AI議事録、AIフィードバック、成約率分析、ベスプラ共有 | roleplay / dashboard（既存）+ AI議事録（新規） |
| 3 | スタッフ | 採用難 / 離職 / 教育コスト / 院長が現場に張り付く | 教育コンテンツ、AIマニュアル、KPIダッシュボード | lessons / roleplay（既存）+ スタッフKPI（新規） |
| 4 | オペレーション | LINE対応 / 電話 / 写真管理 / 二重入力 | AI受付、自動連携、ワークフロー自動化 | line-share / photos（既存）+ 外部連携（新規） |
| 5 | 医療品質 | 経過観察が属人的 / 再診タイミング最適化されず | AI経過観察、リスク検知、自動リマインド | evidence / at-risk / follow-loop（既存）+ リマインド自動化 |
| 6 | **経営管理** | **数字が見えない / 利益率不明 / 施策が打てない** | **経営ダッシュボード + AI経営分析 + アクション提案** | **← 新コア「copilot」。retention/evidence 純関数が部品** |

コパイロットの体験イメージ（これを北極星にする）:
- 「今週は再診率が低下しています。LINEフォロー対象が42名います。→ [一括フォローを送る]」
- 「○○さんは成約率が平均より12%高く、ヒアリング時間は短い傾向です。→ [この型を練習シナリオ化する]」

## やること（成果物・順に）

1. **設計書の改訂**: `docs/accord/saas-design.md` と `topping-architecture.md` を v2 に更新
   - ポジショニング章を「既存システムの上に乗る経営AIレイヤー」に書き換え
   - 上のペイン→価値マップを正式な章として追加
   - 「予約・カレンダーは作らない」の判断は維持しつつ、「**連携はする**（CSV取込 → 将来API）」に発展させる

2. **トッピングカタログ v2**: `src/lib/toppings/registry.ts` に追加（既存IDは変更禁止）
   - `copilot`（新tier検討可。経営コパイロット: 日次ブリーフ + アクション提案。Standard=週次 / Pro=日次+提案実行）
   - `ai-minutes`（AI議事録: カウンセリング録音→構造化記録→フィードバック。roleplay の採点ルーブリックを再利用）
   - `staff-kpi`（スタッフ別KPI: 成約率・ヒアリング傾向。**「責めるためではなく練習テーマを決める材料」の文化を必ずUI文言に**）
   - `data-import`（外部データ連携: 予約/POS/広告CSVの取込。コパイロットの燃料）
   - 依存関係・プラン含有・メーター・単品価格を定義し、既存テスト（整合性・単調性）を green に保つ

3. **コパイロットのデータ設計**: 日次メトリクススナップショット（`metrics_daily`）と
   アクション提案（`copilot_insights`: insight / evidence / proposed_action / status(done/dismissed) / outcome）の
   テーブル設計を saas-design §7.3 に追記。**提案→実行→効果測定が1レコードで追える**こと

4. **インサイトエンジン設計**: ルール層（retention/evidence と同じ**純関数**で「事実」を検出）
   → LLM層（Claude で自然文ブリーフ + 打ち手提案を生成、structured outputs でスキーマ強制）
   → アクション層（提案に Accord 内の実行ボタンを紐付け: LINE一括フォロー / 練習シナリオ割当 等）。
   禁止語フィルタを通し、断定的な因果表現をしない（evidence エンジンの §8 コピー規則に従う）

5. **デモ画面の実装**: `/accord/copilot` を既存デモと同じ流儀（デモモード・フィクスチャ駆動・
   ブランドデザイン維持）で追加。「今日のブリーフ」3件 + 各件に実行ボタン + 実行済みの効果表示。
   ナビとモジュールパネルにも copilot を追加

6. **料金への反映**: `/accord/pricing` の表がレジストリ駆動なので、registry 更新だけで反映される
   ことを確認。コパイロットを Standard 以上の中核価値として配置（Starter には出さない）

## 守るべき制約（変えないもの）

- トッピング機構（registry / can() / 3層判定）はそのまま使う。**新機能は必ずトッピングとして追加**
- 既存デモ4画面・/story・/plans・/hub・senacare CRM は壊さない（追加のみ）
- 同意ファースト（LINE送信はサーバ403強制）、禁止語フィルタ、監査ログの思想
- 「数字は責める道具ではなく練習テーマを決める材料」— スタッフKPIの見せ方はこの文化を最優先
- 予約・電子カルテ機能そのものは作らない（連携に徹する）
- デザインシステム（ブランド茶・クリーム・角丸カード）を維持
