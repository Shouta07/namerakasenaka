**方法**: 本番ビルド（`next build` → `next start`）で 49 ルートを 390 / 820 / 1280px で巡回、
依存の脆弱性・秘密情報・テナント分離・テスト・実装状況を実測。

## 2. 売る前に必ず塞ぐもの（ブロッカー）

### B1. 認証とテナント分離が「デモモード」で無効化されている
`middleware.ts` は環境変数が未設定だと**全ルートを素通し**にする。
デモとしては正しいが、本番テナントを迎える前に、
デモモードと本番モードの切り分け（環境ごとの明示フラグ）が要る。

### ~~B2. 同意なし LINE 送信のサーバ強制が未実装~~ → 検査表示ぶんは実装済み
同意は**フラグではなく記録**（いつ・誰が・何について・どう確認したか）にした。
判定は `lib/labtest/consent.ts` の純関数に集約し、`POST /api/labtest/publish` が
同意なし・取り消し済みの公開要求を **403** で止める。実測で確認済み:
UI を迂回して API を直接叩いても 403、同意を取り消した瞬間から患者側の表示も消える。

**残り**: LINE 送信（`line_share`）の強制は、B4 の配信実装と同時に入れる。
同意の目的は分けてあるので、判定関数はそのまま使える。

### ~~B3. 検査結果の取り込み経路が無い~~ → 実装済み
施術者が検査票をドラッグ&ドロップ（CSV / TSV / コピペ）→ 人が確認 → 同意を確かめて公開。
`lib/labtest/parse.ts` は純関数で、**読めなかった行を捨てずに理由つきで返す**。
患者は一切入力しない。

**残り**: PDF の直接読み取り（いまは「表を選択してコピー」と案内して逃がしている）と、
本番の永続化（`lab_imports` / `consents` テーブル。いまはデモの localStorage）。

### B4. LINE 配信が未実装
`@line/bot-sdk` も Messaging API の設定も無い。
「LINE で届く」を売り文句にしている以上、契約前に必須。

**前提が確定した**: 公式アカウントは**店舗が自分で持っている**。
自社で束ねるのではなく、店舗のアカウントに接続する（BYO-LINE）。
通信費は店舗負担になるが、そのかわり **店舗のチャネルの鍵を預かる**リスクと、
**患者IDが店舗ごとに別物になる**というスキーマ上の制約が乗る。
着手前に `docs/accord/security-and-cost.md` の3章を読むこと —
鍵を預からずに済む方法（モジュール）があれば、設計そのものが変わる。

## 4. 磨き残し（売れるが、直したい）

### 済（2026-08 の磨き込みで塞いだ）

- **タップ領域 44px 未満: 0 件**。390 / 820 / 1280px の3幅 × 49ルートで実測。
  密なUIは見た目を保ったまま当たり判定だけ広げる `.tap-44`（globals.css）と
  `Button size="sm"` の擬似要素で解決した。iPad のサイドバーも 44px に。
  文中に埋まったリンクは WCAG 2.5.8 の inline 例外として対象外
- **横スクロール 0 ページ**（820px のスタッフ画面で3件出ていたものを解消）。
  原因は flex 子の `min-width:auto`。レイアウトの列に `min-w-0` を入れた
- **顧客画面の入力欄 0 件** — 到達不能なまま残っていた `/c/self-log` を削除。
  「顧客は記録しない、やりとりは LINE」の原則とコードを一致させた
- **再発防止**: `src/lib/compliance/__tests__/source-hygiene.test.ts` が
  実在名の再混入・`.tap-44` の消失・顧客画面への入力欄復活を検知する

### 残

- **依存の脆弱性 3件（high）** — `postcss` と `sharp`（libvips CVE）。
  いずれも **Next 15 の内部依存**で、解消には Next 16 への更新（メジャー）が要る。
  **患者の写真を扱う前に上げること**
- TODO/FIXME が 9 箇所。うち 8 件は `TODO(phase-1)` で、
  B1/B3 の本番接続点を指している（消すのではなく、塞いだら消える印）
- 実在名の扱い: **すべて非掲載**（医療機関名・医師名・店舗名・担当者名）。
  画面・識別子・URLスラッグまで除去済み
