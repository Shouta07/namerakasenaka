# Accord ペイン・カバレッジ検証（v2時点）

**目的**: ターゲットペルソナのペインを再度洗い出し、Accord（デモ実装 + v2設計）が
どこまでカバーしているかを1件ずつ検証する。**正直に**ギャップも記す。

**凡例**
- ◎ **デモで動く**（/accord で今日見せられる）
- ○ **設計済み**（v2設計書・トッピングレジストリに定義あり。実装はSaaS化フェーズ）
- △ **部分的・間接的**（効くが正面からは解かない）
- ✕ **未カバー**（ギャップ or 意図的対象外）

**ペルソナ**: 主 = 院長・オーナー（意思決定者）／副 = カウンセラー・スタッフ（日々の利用者）／
終端 = 患者・お客様（価値の受け手。ここが動かないと上流の数字は動かない）

## 1. 集客・経営

| ペイン | 判定 | カバーする機能 | 備考 |

| 広告費が高騰している | △ | data-import（広告CSV）+ copilot | 広告運用自体はしない。CPAの**可視化と気づき**まで |
| 新規CAC が上がっている | △ | roleplay / dashboard | 正面からは解かず、**成約率を上げて「来た人あたりの獲得効率」を改善**する位置取り（意図的） |
| リピート率が低い | ◎ | follow-loop / at-risk / copilot | copilot デモの1件目そのもの（再診率低下→フォロー42名） |
| LTV が伸びない | ○ | follow-loop / lessons / copilot | metrics_daily に revenue 設計あり。LTV算出画面は未定義（軽微） |
| 口コミが増えない | ✕ | — | **ギャップ①**。下記「推奨アクション」参照 |
| キャンセル・無断キャンセルが多い | ◎/△ | copilot（木曜集中→リマインド前倒し）+ follow-loop | 気づき→リマインド変更はデモ済み。予約システム側の実行は連携前提 |

## 集計

25ペイン + 終端3 = 28項目:
**◎ デモで動く: 13　／　○ 設計済み: 5　／　△ 部分・間接: 6　／　✕ 未カバー: 4**

✕ の内訳: 口コミ（ギャップ）／ 売れ筋分析（ギャップ・小）／ 採用（意図的対象外）／ 電話・AI受付（意図的対象外）。
**意図的対象外の2件は戦略（上に乗るAIレイヤー・AI受付は本丸でない）と整合しており、真のギャップは2つ。**

## 推奨アクション（ギャップの潰し方）

1. **ギャップ①口コミ**（価値が高く、実装が安い）:
   copilot のアクション種別に「口コミ依頼」を追加する。効果実感の瞬間（evidence で
   改善トレンド確定時／before-after 共有に好反応が返った時）に
   「〇〇様は改善を実感されています。口コミ依頼の好機です → [LINEで依頼文を送る]」と提案。
   既存部品（evidence + line-share + copilot）の組み合わせだけで作れる。
   → レジストリ変更不要。COPILOT_BRIEF への1カード追加でデモ可能。
2. **ギャップ③売れ筋分析**: metrics_daily に `per_menu jsonb` を1列追加し、
   copilot のルール層に「メニュー別成約・粗利の偏り検出」を足す（設計書の軽微改訂のみ）。
3. **ギャップ②利益率**: P/L 全体には踏み込まない方針を明文化し、営業トークでは
   「粗利の見える化（売上−広告費）まで」と正直に線を引く。会計SaaS連携は M13+ の検討事項。
4. 採用・電話は「やらない」を継続。営業資料でも「そこは既存ツール/HRの領域。
   Accord はその上に乗る」と位置取りの証拠として使う。
